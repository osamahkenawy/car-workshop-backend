Server: ubuntu@130.61.83.110  (workshop.pioneeruae.com)
Backend:  /var/www/car-workshop/backend      pm2 name: car-workshop-backend
Frontend: /var/www/car-workshop/frontend

Deploys: backend 1607faf, frontend 91548b7

JWT secret rotation is DEFERRED to off-hours (it signs out every staff
session and every mechanic app login). Until it is done, the forgeable
staging secret is still live — see step 8.

---------------------------------------------------------------------------
STEP 1 — Pull code
---------------------------------------------------------------------------
  cd /var/www/car-workshop/backend && git pull origin main

/var/www/car-workshop/frontend is NOT a git checkout - it holds the built
output only (assets/ fonts/ index.html). Per deploy/deploy.sh the frontend is
built in a temp checkout at /tmp/car-workshop-frontend-build and the dist is
copied into the web root. Because it lives in /tmp it may be gone after a
reboot, so handle both cases - see STEP 4.

Expect backend at 1607faf (git log --oneline -1).

DO NOT RUN deploy/deploy.sh FOR THIS DEPLOY. It:
  - overwrites backend/.env from /tmp/backend.env, destroying the live JWT
    secret and DB credentials with whatever stale file is sitting in /tmp
  - runs only the old migrations, with mysql -proot and errors hidden by
    || true, so none of the three new migrations are applied
  - pm2 delete + pm2 start instead of restart
  - reloads nginx but never installs the new config
Use the manual steps below.

---------------------------------------------------------------------------
STEP 2 — Backend dependencies
---------------------------------------------------------------------------
  cd /var/www/car-workshop/backend && npm install --omit=dev

No build step: the backend is plain ESM Node.

---------------------------------------------------------------------------
STEP 3 — Migrations (all three are idempotent; safe to re-run)
---------------------------------------------------------------------------
  cd /var/www/car-workshop/backend
  mysql -u root -p car_workshop < src/migrations/20260825_create_user_notifications.sql
  mysql -u root -p car_workshop < src/migrations/20260825_widen_service_status_token.sql
  mysql -u root -p car_workshop < src/migrations/20260825_enquiries_phone_nullable.sql

What they do:
  create_user_notifications   creates the table that never existed, and renames
                              tenant_id/order_id -> workshop_id/work_order_id
                              if an older table is present
  widen_service_status_token  pregenerated_tokens.service_status_token
                              varchar(20) -> varchar(64), or a 128-bit token
                              would be silently truncated
  enquiries_phone_nullable    contact_phone NOT NULL -> NULL, so the website
                              contact form (no phone field) can post

STEP 4 — Frontend build
---------------------------------------------------------------------------
Get the source checkout up to date (clone it if /tmp was cleared):

  FE=/tmp/car-workshop-frontend-build
  if [ -d "$FE/.git" ]; then cd "$FE" && git fetch origin && git reset --hard origin/main;   else rm -rf "$FE" && git clone https://github.com/osamahkenawy/car-workshop-frontend.git "$FE" && cd "$FE"; fi
  git log --oneline -1        # expect 91548b7

Build it (npm install, not npm ci - the lockfile has not been verified in sync):

  cd /tmp/car-workshop-frontend-build && npm install && npm run build

Check the build produced all three entries before replacing anything:

  ls dist/            # must show: assets  fonts  index.html

Only then swap it in:

  sudo rm -rf /var/www/car-workshop/frontend/*
  sudo cp -r /tmp/car-workshop-frontend-build/dist/. /var/www/car-workshop/frontend/
  ls /var/www/car-workshop/frontend/

The rm is safe: everything in that directory is generated by the build.
fonts/ comes from the repo's public/fonts (the Amiri faces used for Arabic
PDF export), so it is restored by the copy - do NOT run the rm unless the
preceding build succeeded and dist/ contains all three entries.

---------------------------------------------------------------------------
STEP 5 — nginx config
---------------------------------------------------------------------------
Copy deploy/car-workshop-nginx.conf from the backend repo over the site file,
then TEST BEFORE RELOADING:

!! DO NOT COPY car-workshop-nginx.conf OVER THE LIVE FILE !!

The live site has a working Let's Encrypt certificate and a 443 server block
that certbot wrote (verified: CN=workshop.pioneeruae.com, expires 2026-10-22).
deploy/car-workshop-nginx.conf is HTTP-only - copying it would delete the TLS
block and take HTTPS down for the whole site.

Use the include snippet instead:

  sudo mkdir -p /etc/nginx/snippets
  sudo cp /var/www/car-workshop/backend/deploy/car-workshop-security-headers.conf /etc/nginx/snippets/
  sudo cp /etc/nginx/sites-available/car-workshop ~/backups/nginx-car-workshop-$(date +%F-%H%M).conf

Then edit /etc/nginx/sites-available/car-workshop and add this line inside each
server block (both the 80 and the 443 one):

  include /etc/nginx/snippets/car-workshop-security-headers.conf;

  sudo nginx -t

Only if that prints "syntax is ok" and "test is successful":

  sudo systemctl reload nginx

If nginx -t fails, restore and stop:
  sudo cp ~/backups/nginx-car-workshop-*.conf /etc/nginx/sites-available/car-workshop

---------------------------------------------------------------------------
STEP 8 — DEFERRED, off-hours: rotate the JWT secret
---------------------------------------------------------------------------
This signs everyone out. Do it when the workshop is quiet.

  openssl rand -hex 32
  # put the value in /var/www/car-workshop/backend/.env as JWT_SECRET=<value>
  pm2 restart car-workshop-backend --update-env

--update-env is required or pm2 keeps serving the old value from its cached
environment, and you will believe you rotated when you have not.
